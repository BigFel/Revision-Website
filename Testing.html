Software Testing

Hope this helps you understand the different types of software testing.

Levels of Testing

  • Unit Testing: Testing individual functions or modules in isolation. This is where you check "one little bit" of code at a time to make sure it works before connecting it to anything else.

  • Subsystem Testing: Testing groups of interacting modules together. This focuses on the "pieces and how they fit together."

  • System Testing: Testing the complete, integrated software against its original requirements. This means "testing the whole thing" as a finished product.

  • Quality Assurance (QA): The overall process and standards used to prevent bugs and ensure the software meets a high standard of quality.

Testing Perspectives (The "Boxes")

  • Black Box Testing: Testing the software's functionality without seeing the internal code. The tester pretends to be the user, checking if the inputs give the right outputs.

  • White Box Testing: Testing the software's internal structure and code. The tester has knowledge of how the software works internally.

  • Grey Box Testing: A combination of both black box and white box testing. The tester has some knowledge of the internal workings but tests from a user perspective.

Pre-Release Testing Phases

  • Alpha Testing: testing done by the company’s own employees, testers, or QA team. It happens in a controlled lab environment and tries to simulate how a user might behave.

  • Beta Testing: testing done by a select group of external users who are given access to the software before its official release. This helps identify any issues that may have been missed during internal testing.
