Conversion Methods

Hope this helps you understand the different methods for converting from old systems to new ones.

Direct Conversion

The old system is stopped completely, and the new system is started immediately.

  • When to use: For non-critical systems or when the old system is completely broken.
  • Risk: High. If the new system fails, there is no backup to fall back on.
  • Cost: Low. You aren't paying to run two systems at once.

Parallel Conversion

The old system and the new system run at the same time for a set period.

  • When to use: For critical systems like banking or hospitals where data cannot be lost.
  • Risk: Very Low. If the new system has a bug, the old system is still there as a backup.
  • Cost: High. You have to pay for the hardware and staff to run two systems, and data has to be entered into both.

Phased Conversion

The new system is introduced in stages. One part of the software is installed, then another, until the whole system is replaced.

  • When to use: For very large, complex software packages with many different modules.
  • Risk: Medium. If a problem happens, it only affects one part of the business at a time.
  • Cost: Medium. It takes a long time to complete the full transition.

Pilot Conversion

The new system is installed at one small "test site" (like one branch office or one classroom) before being rolled out to the rest of the company.

  • When to use: For organizations with many different locations.
  • Risk: Low. If the system fails, it only affects the small pilot group.
  • Cost: Medium. It requires extra support for the pilot group during the trial phase.
