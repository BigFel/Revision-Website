Software Maintenance

Hope this helps you understand the different methods for maintaining existing software systems.

What is Software Maintenance?

Maintenance is the process of modifying a software system after it has been reached the user. It is often the longest and most expensive part of the software life cycle.

Why is it necessary?

  • Fixing Bugs: Correcting errors in the source code that weren't found during testing.
  • Changing Requirements: Modifying the program because the user's needs or the laws have changed.
  • Compatibility: Ensuring the software works with new hardware, operating systems, or other software.

The Patch: A patch is a specific piece of code inserted into an existing executable program to fix a problem without needing to reinstall everything.

Managing Changess

Modifying code is a delicate process because a change in one area can cause "side effects" in another.

  • Side Effects: When fixing one function accidentally breaks a different part of the program that relies on it.
  • Testing Changes: Any modification to a routine must be tested just as thoroughly as the original module was tested.
  • Maintainability: This is a measure of how easily a software solution can be understood, repaired, and evolved over time.

Tools for the Maintenance Programmer

Maintenance is rarely done by the same people who originally built the software. They rely on specific tools to understand the code:.

  • System Models: Accurate models (like Flowcharts or DFDs) help programmers find the exact section of code that needs to be altered.
  • Data Dictionaries: These tell the programmer exactly what each variable does and what its data type is, preventing data corruption during an update.
  • Structure Charts: These show the "hierarchy" of the program, helping the programmer see which other modules might be affected by a change.

How to Prioritise Upgrades

When a software has thousands of users, there will be too many requests to fix everything at once. Developers must prioritize based on:

  • Frequency of Error: How often are users encountering this issue?
  • Impact of Error: Is it just a typo, or does the program crash and lose data?
  • Cost and Time: Is it worth the money and hours required to fix it?
